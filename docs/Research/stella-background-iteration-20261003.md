Официальные исходники и README закреплены в [пакете](lumicells-20260930/upstream/lumicells-1007717d72cfd9d768d4b9a3f7fc80a126e49c51/README.ru.md). Нового шейдера/движка нет. Реальная интеграция/опыт применения: [предыдущая визуальная итерация](../../artifacts/reports/stella-ux-iteration-20261003.md) и последующий пользовательский отзыв — активная light-привязка создаёт нежелательные яркие клетки вокруг элементов.

Подтверждено кодом:

- schema/schema.ts: `lift.enabled` отключает поднятые клетки; `modes.rain.weight` по умолчанию уже0. Значит называть наблюдаемый эффект именно rain-mode нельзя: текущий адаптер явно включал lift.amount0.3, дополнительно hover инициировал lift. Убираем эти источники, sparkle тоже0.
- background.spotA/B и vignette реализованы в native composite.ts. Пятно — гауссово, координаты относительно центра host; vignette темнит фон, но не клетки. Сетку делаем чуть спокойнее её собственными brightness/floor, не размытием тела клетки.
- `data-lc-influence="shadow"` и `bindElement({type:'shadow'})` — документированные API. В field.ts shadow множит яркость клеток вниз, light наоборот прибавляет яркость. DOM tracking сохраняет правильную область во время движения.
- CSS box-shadow даёт непрерывную мягкую тень у края самой плашки; native shadow подавляет пиксельное свечение за ней. WAAPI/Motion, теги, hit-targets и сценарий сохраняются. Клик-pulse остаётся кратким откликом, постоянной light-подложки больше нет.

Критерии: нет фоновых поднятых/мигающих частиц; центральное пятно светлее углов; вокруг кнопок и тегов нет ярких пиксельных прямоугольников, видна мягкая тень; полёты/клики продолжают работать. Параметры пятна — начальная художественная настройка, не доказанное пиксельное совпадение. Визуальная проверка ждёт скриншота пользователя; браузер не открывается по его правилу. Selectel не обновляется этой итерацией.
