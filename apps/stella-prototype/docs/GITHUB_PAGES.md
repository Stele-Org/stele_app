# Тестовая сборка на GitHub Pages

Как дать внешним тестировщикам ссылку на Стеллу. Сайт собирает и публикует GitHub по кнопке; на компьютере тестировщика ничего ставить не нужно.

Адрес после публикации: <https://bntsk.github.io/stele_app/>

## Что получит тестировщик

- Экран «Стела · тестовая версия» с кнопкой «Начать». Одно нажатие нужно, чтобы браузер разрешил звук.
- Приветствие на стартовом экране — звучит само, без параметров в адресе.
- Любая камера: встроенная или внешняя веб-камера. Браузер спросит разрешение.
- Локальный сценарий VK Видео и MAX, включая съёмку при сканировании и экран проверки фото.

Чего в тестовой сборке нет:

- Стендового режима (`?master=1`): ему нужен MASTER.
- Сохранения фото в `PhotoStorage`: это умеет только dev-сервер. Фото остаётся в браузере тестировщика и пропадает при нажатии кнопки.

## До первого запуска: два условия

1. **Сайт на Pages открыт всем, у кого есть адрес.** Логотипы, шрифты и студийные записи проекта предоставлены для закрытой работы ([NOTICE.md](../../../NOTICE.md)). Публикуйте только с согласия правообладателя. Закрыть сайт паролем средствами GitHub можно только на тарифе Enterprise Cloud.
2. **Репозиторий приватный.** Pages из приватного репозитория доступны на платных тарифах GitHub (Pro, Team, Enterprise). Если в настройках Pages вместо выбора источника предложение сменить тариф — тариф не подходит. Тогда либо сменить тариф, либо публиковать сборку из отдельного публичного репозитория.

## Настройка, один раз

1. Файл сценария `.github/workflows/pages-test-build.yml` должен быть в ветке `main` на GitHub. Пока его там нет, кнопки запуска на GitHub не будет.
2. Откройте репозиторий на GitHub → **Settings** → **Pages**.
3. В блоке **Build and deployment** в списке **Source** выберите **GitHub Actions**.

## Публикация

1. Репозиторий на GitHub → вкладка **Actions**.
2. Слева выберите **Test build to GitHub Pages**.
3. Справа **Run workflow** → ветка `main` → **Run workflow**.
4. Дождитесь двух зелёных шагов, `build` и `deploy`. Обычно это несколько минут.
5. Адрес сайта показан в шаге `deploy` и в **Settings** → **Pages**.

Чтобы обновить сайт после новых правок, отправьте их в `main` и запустите сценарий ещё раз. Сам он не запускается.

## Что отправить тестировщику

> Откройте <https://bntsk.github.io/stele_app/> в Chrome или Edge на компьютере с веб-камерой и включённым звуком. Нажмите «Начать» и разрешите доступ к камере.

Параметры адреса для тестовой сборки:

| Адрес | Что меняется |
| --- | --- |
| <https://bntsk.github.io/stele_app/> | Обычный запуск: приветствие и любая камера |
| <https://bntsk.github.io/stele_app/?greeting=0> | Без приветствия |
| <https://bntsk.github.io/stele_app/?voice=debug> | Журнал закадрового голоса в консоли браузера |

Диагностика камеры всегда пишется в консоль браузера, строки `[stella-camera]`: по ним видно, почему камера не запустилась.

## Как снять сайт с публикации

**Settings** → **Pages** → меню с тремя точками рядом с адресом сайта → **Unpublish site**. Ссылка перестанет открываться; повторный запуск сценария публикует сайт снова.

## Если что-то не работает

| Что видно | Причина и что сделать |
| --- | --- |
| На вкладке Actions нет «Test build to GitHub Pages» | Файл сценария не в ветке `main` на GitHub |
| В Settings → Pages нет выбора Source | Тариф не даёт Pages для приватного репозитория |
| Шаг `deploy` отклонён | Сценарий запущен не из `main`: в **Settings** → **Environments** → `github-pages` публикация по умолчанию разрешена только из основной ветки |
| Шаг `build` красный | Откройте его журнал: ошибка сборки или типов. Локально то же проверяет `.\scripts\stella.ps1 build-check` |
| Сайт открывается, камера не работает | Тестировщик не дал разрешение или камеру занял другой сайт или программа. Разрешение меняется значком слева от адреса |
| Нет приветствия | Звук выключен на компьютере или во вкладке, либо в адресе `?greeting=0` |
| Страница 404 сразу после публикации | Подождите минуту и обновите страницу: адрес появляется не мгновенно |

## Чем тестовая сборка отличается от стендовой

Одной переменной при сборке, `VITE_STELLA_TEST_BUILD=1` (`src/app/test-build.ts`). Она включает любую камеру вместо стендовой BRIO, приветствие по умолчанию и стартовый экран с кнопкой. Стендовая сборка делается без этой переменной и ничего из этого не содержит: камера там по-прежнему только BRIO.

Собрать тестовую сборку локально, чтобы посмотреть до публикации (PowerShell, из папки `integrations/master/stella-candidate`):

```powershell
$env:VITE_STELLA_TEST_BUILD = '1'
node node_modules\vite\bin\vite.js build --base=/stele_app/ --outDir .cache/pages-check --emptyOutDir
$env:VITE_STELLA_TEST_BUILD = $null
```

Папку `dist` эта команда не трогает.
