## Файлы и запуск

Рабочая папка: `artifacts/stella-prototype/voice/`. В `vasilisa/reference.wav` объединены5 исходных записей; `vasilisa/phrases.json` содержит19 реплик. Клон Qwen TTS создан для `qwen3-tts-vc-2026-01-22`. Его ID и endpoint credentials находятся только в secrets.

Готовые файлы: `artifacts/stella-prototype/public/voice/vasilisa/*.wav` и `manifest.json`. Vite/сборка копирует их как обычные public assets. Клиент использует Howler2.2.4/MIT через `src/features/voice/use-screen-narration.ts`. Запросов к провайдеру в runtime нет, новые зависимости сервера не нужны.

Из корня D: `node artifacts/stella-prototype/voice/scripts/qwen-voice.mjs` генерирует недостающие/изменённые записи; существующий голос переиспользуется. После изменения текстов заново выполнить генератор, затем перезагрузить страницу. Ключи никогда не добавлять в manifest или Vite env.

## Поведение

- Реплика выбирается по смысловому экрану, индексу вопроса или миссии MAX.
- Входной splash и вылеты ответов молчат; инструкция звучит после splash.
- Новый экран останавливает предыдущую запись. Нет очереди и повторения от обычного rerender.
- Host pause, скрытие документа и условия приостанавливают запись; возвращение продолжает текущую.
- Завершение аудио не меняет ход анкеты. Логотипы и background не перемонтируются.
- При недоступном manifest/файле UI остаётся рабочим; системный голос не подставляется.
- Первое воспроизведение браузер может разрешить только после клика. После разблокировки воспроизводится актуальная подсказка.

Камера: «Смотри в камеру!», FFmpeg atempo1.2 без изменения высоты голоса, чтобы уложиться в существующие1,8с. Остальные записи с исходным темпом синтеза. WAV приведены к завершённым PCM16 mono24кГц, поскольку сервис возвращал заголовки потокового WAV.

Диагностика: `?voice=debug` выводит в console.debug `[stella-voice] <cue> <event>`: play/pause/stop/end/playerror/loaderror. Без параметра логов нет. Это техническая проверка воспроизведения, а не подтверждение сходства тембра.
