# Работа над Стеллой

Сначала читать README.md и docs/context/CURRENT_STATE.md. Две версии: standalone в artifacts/stella-prototype и отдельный master adapter в integrations/master/stella-candidate. Не подменять одну другой.

- Работать короткими проверяемыми итерациями. Сохранять пользовательские изменения; новые ветки codex/*.
- AI по умолчанию отключён. Платные вызовы, enrollment и повторные попытки генерации — только по явному поручению. Никогда не включать AI ради тестов.
- Секреты, private voice state, реальные фото/аудиосессии, SQLite и журналы jsonl не коммитить. Использовать ignored local directories/env; не выводить ключи.
- По независимым задачам подключать субагентов с непересекающимся владением файлами.
- Сначала изучать готовые механизмы и официальные источники; использовать существующие Motion/LumiCells/Howler/Dexie/XState, не дублировать их самописными аналогами.
- Не менять F/master и не деплоить сайт без поручения. Backend reference здесь документальный, не второй мастер стенда.
- Проверять typecheck, релевантные tests и build. По прямому указанию пользователя05.10.2026 визуальные/браузерные проверки выполняет пользователь; агент не запускает браузер или headless без нового прямого запроса. Технические проверки обязательны. Тяжёлые GPU/нагрузочные прогоны и запись видео согласовывать отдельно.
- Исследования: docs/Research; фактические проверки: artifacts/reports; эксплуатация: apps/stella-prototype/docs. После изменений обновлять текущий статус и журнал в docs/context.
- Бренд MAX писать латинскими заглавными. Сохранять постоянные логотипы, плавные переходы и камеру до фактического завершения exit.
- Перед push выполнить Gitleaks по рабочим файлам и Git-истории. Не исключать найденный секрет общим allowlist; сначала разобраться.
- Клиентские материалы и LumiCells не объявлять MIT: сохранить notices/provenance/permission.

Исторические D→F правила в docs/d_to_f_import полезны для контекста; локальные пути исходного монорепозитория не являются путями этого репозитория.
