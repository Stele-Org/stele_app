# ResultStorage

Сюда dev-сервер Стеллы складывает итоги теста VK Видео: один файл JSON на одного посетителя. В файле ответы, теги, тематики с очками, выбор Discovery и сведения о фото — то, что должно отразиться на стене VK Видео и на странице по QR-коду.

В git попадает только этот файл: всё остальное содержимое папки игнорируется (`.gitignore`). Папка не очищается сама, удаляйте файлы вручную.

## Когда появляется файл

Файл записывается в момент, когда посетитель сделал последний выбор, до анимации Discovery и финального экрана:

| Третий ответ | Что считается последним выбором |
|---|---|
| Любой, кроме «Хочу стать героем VK Видео» | Сам третий ответ |
| «Хочу стать героем VK Видео», затем «Пропустить» | «Пропустить» |
| «Хочу стать героем VK Видео», затем «Начать» | «Продолжить» на экране проверки фото |

Если посетитель ушёл раньше последнего выбора, файла не будет. На одну сессию пишется один файл; повторная отправка той же сессии второй файл не создаёт и первый не меняет.

Имя файла — время записи по UTC и идентификатор сессии:

```
20261007T101500Z_4f0c2c1e-6a51-4b8e-9d3f-2b7a9c1e5d10.json
```

Имена сортируются по времени: самый новый итог — последний по алфавиту. Пока идёт запись, файл называется `*.part`; под своим именем он появляется уже целиком. Файлы `*.part` читать не нужно. Кодировка UTF-8.

## Поля

- `schemaVersion`, `type` — версия и вид документа. При несовместимом изменении формата версия вырастет.
- `sessionId` — идентификатор сессии посетителя; тот же, что в имени файла.
- `createdAt` — время последнего выбора, UTC.
- `answers` — ответы по порядку: три вопроса, а для героя четвёртым идёт шаг фото (`questionId: "photo"`, ответ `accept` или `skip`). У каждого ответа свои теги.
- `tags` — все теги ответов подряд, каждый один раз. Это полный набор тегов посетителя.
- `themes` — все восемь тематик от лучшей к худшей: очки (`score`), место (`rank`) и признак вхождения в первую тройку (`selected`).
- `selectedThemes` — первая тройка тематик, то же, что `selected: true`.
- `discovery` — третий ответ и правило подборки для него из таблицы клиента.
- `photo` — что с фото посетителя, см. ниже.

## Тематики: что важно знать

Очки дают только первые два ответа: +2 одной тематике и +1 другой, всего шесть очков на посетителя. Третий ответ и фото на очки не влияют.

- Тематики с равными очками стоят в случайном порядке, который разыгран для этого посетителя один раз. В половине сочетаний ответов очки ложатся 2, 2, 1, 1 — тогда третья тематика выбрана случайно из двух с одним очком.
- В другой половине сочетаний очки получают только три тематики. Тематики с `score: 0` посетитель не выбирал: их порядок случаен и ничего не значит. Если правило требует «тематику 4», проверяйте её `score`.

Названия тематик — как в таблице клиента «Метаданные VK Видео и MAX». Отдельных идентификаторов тематик в документе нет.

## Фото

| `photo.status` | Значение |
|---|---|
| `not-requested` | Фото не предлагалось: третий ответ не «Хочу стать героем VK Видео» |
| `skipped` | Посетитель нажал «Пропустить» |
| `accepted` | Посетитель одобрил снимок; `captureId` — номер снимка |
| `unavailable` | Посетитель согласился на фото, но снимка нет: камера недоступна или кадр не удался |

Снимок с номером `captureId` лежит в папке [PhotoStorage](../PhotoStorage/README.md): файлы `*_<captureId>.jpg` и `*_<captureId>.json`. Он записывается одновременно с итогом, отдельным запросом, поэтому может появиться на долю секунды позже файла итога.

## Что сохраняется, а что нет

- Сохраняется только тест VK Видео, пройденный до последнего выбора. Тест MAX итога не пишет.
- Работает только с dev-сервером (`.\scripts\stella.ps1 dev`) в локальном сценарии. В собранном приложении и на стенде этой папкой никто не пользуется: там ответы уходят в MASTER, и итог считает он.
- Запуск со ссылок предпросмотра, которые начинают с середины сценария (`?discovery=…`, `?reveal=…`), итога не пишет: за ними нет ответов.

## Внешний доступ

Это обычная папка с файлами, поэтому доступ к ней даётся средствами системы или сети:

- открыть папку как сетевой ресурс Windows только на чтение;
- синхронизировать папку на другой компьютер;
- перенести хранилище в уже общую папку: задайте переменную окружения `STELLA_RESULT_STORAGE` с полным путём до запуска dev-сервера.

Сам dev-сервер слушает только `127.0.0.1`. Адреса для чтения итогов по сети у него пока нет: итог забирают из папки.
